# Webview shell bridge (#91, C++ component)

`inkstow-webview` is the only desktop executable; the Qt app and Qt-only tests have been retired. The local `src/frontend/index.html` template and pinned CodeMirror dependencies are bundled into one HTML page at build time, embedded in the executable. `set_html` needs no network or runtime asset paths. The page contains no links or remote assets; its CSP disallows connections and hashes its inline script (CodeMirror's dynamically generated styles require inline CSS). A native fail-closed navigation policy is installed before the vault binding: only the first inline-document navigation used by `set_html` is allowed (`about:blank` on Linux/macOS, a base64 HTML data URL on WebView2); later navigation (including another `about:blank`), subframes and popups are refused. Linux uses WebKitGTK policy decisions, macOS a WKNavigationDelegate, and Windows WebView2 navigation/frame/popup events. This is required because the pinned webview library injects bindings in navigated documents; frontend CSP cannot enforce it. The shell provides a native open-folder picker; the bridge also accepts an absolute UTF-8 vault folder string from the frontend. Use disposable vaults only.

## Contract v1

The native `webview_bind` exposes `window.inkstowRequest(request)` returning a Promise resolving to an object. The binding supplies a JSON array containing exactly one object to `Bridge::handle`; never call `Bridge::handle` with the bare request. Requests are serialized (single window/UI thread), with exact fields and case-sensitive operation names:

| operation | additional field | result |
| --- | --- | --- |
| `open` | `folder`: absolute UTF-8 folder path | opens vault; resets selected note; returns sorted list |
| `list` | none | returns cached note list (not a filesystem refresh) |
| `select` | `path`: vault-relative UTF-8 Markdown path from list | loads decoded editor text |
| `edit` | `content`: complete new UTF-8 editor text | updates unsaved text; no disk write |
| `save` | none | writes selected note through portable `Session` |

Every successful response is `{ "ok": true, "notes": ["path.md"], "path": "path.md", "content": "text", "dirty": false }`. `path` and `content` are empty when no note is selected. Failed operations normally return the same snapshot with `ok: false` and a human-readable `error`; failed open/select/save preserve selection and edits. Invalid JSON/UTF-8 may yield only `{ "ok": false, "error": "Invalid JSON or UTF-8 in request or response." }`. Always check `ok` and display `error` visibly, never discard unsaved `content` on error. Errors resolve the Promise rather than reject it. An `edit` must precede save; editing does not merge incremental deltas. A successful `save` clears `dirty`. Opening or selecting while dirty is refused by `Session`. The frontend configures CodeMirror's line separator from the selected note, preserving uniform CRLF, LF or lone-CR endings on edits and saves, including notes with a UTF-8 BOM. U+2028, U+2029 and NBSP remain text, not line separators. For a note mixing CRLF, LF and/or lone-CR, the frontend visibly disables editing and saving to avoid changing its bytes; selecting another clean note remains possible. Mixed-ending editing remains unsupported in the shipped WebView editor; such notes are read-only to protect their bytes.

Unknown fields, missing/wrong-type fields and unknown operations fail; the complete binding argument JSON is capped at 8 MiB, `content` at 4 MiB, and path/folder at 4096 UTF-8 bytes. The portable core validates paths, note availability, UTF-8, BOM preservation and guarded saves. The original v1 contract above was extended with note actions, conflict decisions and attachment handling; see the current bridge implementation and tests for those operations. List is a snapshot from the last successful open, refreshed by the shell watcher. These historical v1 limits are not a description of the current application.

## Link interaction extension (#95)

The frontend uses `link` for rendered local links and source-link shortcuts, without a separate link-entry panel. It decodes URL escapes in local Markdown destinations, but does not follow encoded `#` or `|` delimiters as fragments or aliases. The portable session resolves the target once, selects Markdown notes (including extensionless links with dots and fragment links), or returns a revalidated attachment path for the shell. When a safe internal Markdown target is missing, it creates and opens an empty note near the source (or at the vault root for root-relative links); explicit non-Markdown targets cannot create notes. Unsaved-edits refusals remain in the portable session. The legacy `follow` and `attachment` bridge operations remain available, but have no separate frontend controls. `external` accepts exactly `{ "operation": "external", "url": "https://example.org/path" }`, refuses missing/dirty selection, validates the HTTP(S) scheme and authority, rejects whitespace, controls, backslashes and credentials, and invokes an injected native default-browser opener. It never navigates the embedded webview. A failed opener returns an error snapshot; a refused link leaves edits intact. The link text in CodeMirror is presentation only, never a replacement for the source passed to `edit` or `save`.

The WebView shell is always built; `INKSTOW_BUILD_WEBVIEW=OFF` and Qt-only builds are no longer supported. CTest runs headless `inkstow-tests` cases and Node editor tests; native Linux navigation and real-window cases run under Xvfb when `xvfb-run` is available. On macOS and Windows, real-window cases run natively.

Dependencies: CMake FetchContent retrieves checksum-pinned `webview/webview` 0.12.0 (SHA256 `e2c8d0bed3fcd13e624074448b7d3b1d0b0d03546a15839f17ee0013f2cba1db`) and `nlohmann/json` 3.12.0 (SHA256 `4b92eb0c06d10683f7447ce9406cb97cd4b453be18d7279320f7b2f025c10187`) at first configure; subsequent builds use the CMake cache, and a clean offline configure needs pre-populated FetchContent archives. Linux uses system WebKitGTK 4.1/GTK3; macOS uses WKWebView, Windows WebView2 (Evergreen runtime required). The release pipeline builds, tests, packages and smoke-launches the WebView app on Linux, macOS and Windows. Manual platform checks for OS pickers and default attachment handlers still require disposable vaults; do not infer Qt feature parity from the removal of Qt.
