# Inkstow

Prototype of a non-Electron Markdown vault editor with a Qt-free C++20 vault core, a native system-webview shell, and an offline CodeMirror frontend. A disposable example vault lives at `tests/fixtures/sample`. Qt is no longer built or shipped; this cutover does not claim feature-by-feature parity with the former Qt app.

## Install and run

On Debian/Ubuntu Linux (macOS notes follow):

```sh
sudo ./scripts/install --system   # WebKitGTK, Node/npm, CMake, and C++ compiler
cmake --preset debug      # or: release
cmake --build --preset debug --parallel   # WebView app and portable core
cmake --build --preset debug --target unit-tests --parallel
ctest --preset debug
./build/debug/inkstow-webview     # graphical X11 desktop
```

On macOS, install Xcode or its Command Line Tools and [Homebrew](https://brew.sh), then run `./scripts/install --system` without `sudo` (it installs CMake and Node) and the same CMake build and CTest commands. Launch the macOS bundle with `open build/debug/Inkstow.app`. It uses the system WKWebView. The project and its presets require CMake 3.21+.

On other systems, install CMake 3.21+, Node.js 18+ and npm, a C++20 compiler (GCC 11+, Clang 14+, AppleClang 14+ / Xcode 14+, or MSVC 2022 / 19.30+), and the platform WebView SDK. Windows requires the WebView2 Evergreen runtime and Visual C++ Redistributable to run the bundled app. CI builds and tests on Ubuntu 24.04, macOS 15 arm64, and Windows 2022; platform release packaging is also exercised on PRs.

Open a vault folder with **Open vault…** (also **File > Open vault…**, Ctrl+O / Cmd+O), which shows a folder picker. Inkstow reopens the last vault on the next launch; if that folder is gone or can't be opened, it shows the empty state with the reason. To avoid altering the checked-in fixture, first copy it to a throwaway directory:

```sh
vault=$(mktemp -d)
cp -a tests/fixtures/sample/. "$vault/"
printf '%s\n' "$vault"
```

Open that folder in Inkstow. Only `Welcome.md` and `Folder/Second note.md` should appear, with `Second note.md` inside the expandable `Folder` group; dot-prefixed files and folders are excluded from discovery. Edit and save a note with Ctrl+S (Cmd+S on macOS), then confirm the copied file changes on disk. Unsaved edits must block switching notes or vaults. Try creating, moving and trashing a throwaway note, then trigger an outside-change conflict and choose **Reload from disk**, **Keep mine**, or **Merge outside changes**. For link behavior, open a disposable copy of `tests/fixtures/links` and follow `[[Twin]]` in `A/Source.md` with Alt+Return (Option+Return on macOS). See the WebView smoke steps below for native picker, attachment, quit and watcher checks. The Qt-only highlighter appearance and widget interactions are no longer shipped; the CodeMirror editor offers Live Preview, but feature-by-feature Qt parity was not a retirement gate.

## Sandcastle/Pi issue workflow (Linux Docker)

This optional unattended workflow needs Docker, Node.js 22.19+, npm, `gh` logged into `pcheng17/inkstow` with issue/PR access, and an `origin` remote with push access. Use a clean checkout; `npm ci` installs the pinned local harness dependencies. Build the pinned sandbox image once, then sign in to Pi's **dedicated** profile inside an interactive container (type `/login` and follow its instructions):

```sh
npm ci
npm run sandcastle:build-image
npm run sandcastle -- --login
npm run sandcastle -- --check 123  # read-only GitHub eligibility/branch gate and isolated Pi auth check
npm run sandcastle -- 123          # implement issue #123
```

The host checks `ready-for-agent`, native blockers, parent and comments, refuses an existing local or remote `sandcastle/issue-123` branch, and fetches `origin/main`. It creates a new worktree on that base, preflights the sandbox's `openai/gpt-6-sol` login (the provider name used by Pi's OpenAI OAuth flow in this image), and only then allows any issue updates. The implementer follows TDD, simplifies in the same session, and commits green slices. The host requires clean committed changes, builds the WebView app, unified C++ tests and `vault-inspect`, runs CTest and, for C++ changes, checks clang-format and `scripts/check-clang-tidy.py`. Fresh serial Standards and Spec reviewers and a fresh PR writer get only Pi's read tool and a host-captured diff; HEAD and status are checked after each pass. Up to two review fix rounds are allowed. Only the host pushes and opens a PR; it never merges. The host then comments with the PR URL or marks a blocked run `needs-info`.

The image checks out a pinned commit of `pcheng17/harness-kit` and runs `uv run --locked harness-kit install --harness pi`, installing its Pi package, agents, skills, and instructions. The issue workflow still asks each pass to work alone; installation does not enable agent delegation in those prompts. Harness Kit does not include `pi-web-access`, so its web-research agents require that separate extension if used.

The login profile lives at `~/.local/share/inkstow/sandcastle-pi/agent` (private permissions), not the regular host `~/.pi/agent`; do not copy host credentials into it. The container receives this profile and the worktree, not host `gh` credentials. It mounts the profile at a separate path and links only its auth and model-store files into Pi's config directory; mounting over `~/.pi/agent` would hide the package registration installed in the image. Existing profile `settings.json` is not loaded inside the container. `--check` does not create a branch, comment, change labels, push, or open a PR; it does fetch `origin/main` locally. Auth/image/network or verification failures stop the run. A failed run can leave a durable branch (and a dirty worktree is preserved); inspect that branch before rerunning or removing it. Logs are under `.sandcastle/logs/`, and verification prints bounded output. The local gate requires Linux Docker/WebKitGTK; macOS and Windows build/test checks remain CI's responsibility. Never point manual verification at a personal vault; use `tests/fixtures/sample` or a throwaway vault.

## Making a release

Releases are started manually from **Actions > Release > Run workflow**, on `main`. First merge a PR changing `project(Inkstow VERSION ...)` in `CMakeLists.txt` to the intended `MAJOR.MINOR.PATCH` version. Enter that version without the `v` in the workflow form. The workflow refuses non-`main` runs, version mismatches, and existing tags. It builds and runs CTest on all three release runners before creating the immutable `vMAJOR.MINOR.PATCH` tag and GitHub Release. Do not create the tag by hand. A failed build creates no release; if publishing fails after the tag or draft release was created, inspect that draft and the workflow logs before any manual recovery. Do not retag an existing release to a different commit.

The release contains unsigned WebView bundles without Qt: a Linux x86_64 tarball (extract and run `inkstow/inkstow-webview` on an X11 desktop with compatible glibc, GTK3 and WebKitGTK 4.1 installed), a macOS arm64 zip file for Apple silicon (unzip and open `Inkstow.app`; no Intel Mac download is provided), and a Windows x86_64 zip file (unzip and run `inkstow-webview.exe`, with WebView2 Evergreen and the Visual C++ Redistributable installed). Each archive includes `RUNTIME.txt` describing external dependencies. The release workflow reports compressed and unpacked shipped bytes for each platform; external system runtimes are not included in those sizes. It also contains `SHA256SUMS`. These are not installers. macOS Gatekeeper and Windows SmartScreen may warn about unnotarized/unsigned applications; do not bypass security warnings for downloads you cannot verify. PR CI builds and tests the app on these systems; the release workflow runs its Linux, macOS and Windows release build, CTest, bundle and smoke checks on PRs without publishing. Only manual dispatch on `main` publishes a release. A first real release should be downloaded and smoke-tested on each target OS before announcing it.

## Pre-commit hook

The `.githooks/pre-commit` hook auto-formats staged `.h` and `.cpp` files with `clang-format` before each commit. Install `clang-format` 21 or newer (older versions reformat already-formatted code) and activate the hook once after cloning:

```sh
git config core.hooksPath .githooks
```

## Clang-tidy check

Configure with WebView enabled and build all checked targets so the compilation database includes the shell and test sources, then run the same check as CI from the repository root:

```sh
cmake --preset debug
cmake --build --preset debug --target inkstow-webview unit-tests vault-inspect --parallel 2
python3 scripts/check-clang-tidy.py
```

The script uses `clang-tidy` on your PATH by default; pass `--clang-tidy clang-tidy-18` to use CI's pinned executable. It refuses missing compilation entries and treats lint warnings as errors. On Linux it checks the Linux navigation implementation and native-navigation test entries (the latter needs Xvfb at configure time); on macOS and Windows it skips these Linux-only sources. Platform-specific macOS/Windows navigation implementations are not covered by this check. The clang-tidy CI job runs on Linux.

## Headless tests

The default build compiles `inkstow-webview` and its portable core. Build `unit-tests` explicitly before CTest; it builds the single C++ runner `inkstow-tests` and offline JS assets. CTest runs the headless C++ cases without a display, the native-navigation and real-window cases under Xvfb on Linux (native windows on macOS/Windows), and Node editor tests separately. Install `xvfb-run` on Linux to register the window cases. To inspect a disposable vault, build `vault-inspect` explicitly with `cmake --build --preset debug --target vault-inspect`, then run `./build/debug/vault-inspect tests/fixtures/sample` or pass another throwaway vault path.

## Boundaries and limitations

This is an early prototype, **not** a safe replacement for Obsidian on valuable vaults. It can rename/move individual notes but cannot rename folders. Link updates preflight all discoverable Markdown notes, refuse complex relevant wikilinks (aliases, fragments, embeds), invalid UTF-8, and unresolved relevant links; they rewrite simple affected links to root-qualified paths without `.md`, rather than copying Obsidian's shortest-link serialization. If an extensionless file would shadow a rewritten link, or a basename already ends in `.md`, link updates refuse the move before changing any files. Names containing wikilink delimiters (`#`, `|`, `[`, `]`, or newlines) are also refused for link updates. Case-only renames are not supported on case-insensitive filesystems. UTF-8 BOMs are preserved. Choosing not to update links may break them. The move and rewrites are not a filesystem transaction: later write failures may leave a moved note and partially updated links (the error reports this). External writes can race preflight and per-file replacement. **Follow link** resolves Markdown notes and opens attachments in the system's default app, but its target ordering and case handling are provisional and have not been checked against a running Obsidian. Heading fragments select the file, not a position within it; block references and embeds are not supported. It watches the open note: outside changes reload a clean editor, while unsaved edits are kept and a bar offers to reload from disk or keep your version. **Keep mine** only replaces the outside version that was reported, and reloading can be undone. **Merge outside changes** combines disjoint line edits and marks overlapping edits, including deletion versus change. Very large notes are refused by the line merge rather than exhausting memory. The merged editor text remains unsaved and Save still refuses a newer outside change. If a note is deleted outside Inkstow while you have unsaved edits, the bar offers **Save as new note** to recreate the selected path without replacing a reappeared file, or **Discard edits**. The note list refreshes when watched vault folders change or when the window is reactivated. Large vaults may exceed the OS limit on watched paths, so some changes may not appear until reactivation. New notes need a vault-relative path whose folders and name don't start with `.`; `.md` is added when missing, and an existing file is never replaced. On Linux and macOS, trash without an available system trash refuses; on Windows the portable core uses the interactive Windows Shell: if Windows cannot recycle a note, it can offer permanent deletion. **Cancel that prompt if you need the note to remain recoverable**. Confirming permanent deletion cannot be undone from the Recycle Bin; see "Portable note actions" below. Saves stage a same-directory replacement. Replacement can change inode and metadata; hard links are not preserved. The WebView editor preserves uniform CRLF, LF and lone-CR line endings, but mixed-ending notes are read-only to protect their bytes. Markdown must be valid UTF-8 to open in the editor. The vault core rejects path traversal and never reads or writes a note through a symlink, but filesystem races have not been hardened. Use only disposable copies for now.

### Save conflict guarantee

Inkstow compares a note's disk bytes with the last loaded or saved bytes before saving, then compares again just before committing the staged replacement. If either comparison finds different bytes, the save is refused and your unsaved edits stay in the editor. This is best-effort conflict detection, **not** a guarantee that outside changes cannot be lost: another program (including another Inkstow instance) can write after the final comparison and before the replacement, and its write may be overwritten. Atomic replacement keeps Inkstow from leaving a partially written note, but does not make the comparison and replacement atomic together. On Windows, a transient lock can prevent atomic replacement; Inkstow retries a few times, checking the original bytes before each attempt, and leaves edits unsaved if the lock persists. Inkstow does not coordinate saves with other processes or guarantee recovery of a write lost in that window. Use independent backups for valuable vaults.

## Portable vault and recovery migration (#88, #89)

`portable-core` (`src/core/vault/`) is a standalone C++20 library with no Qt dependency. `inkstow::portable::Vault::open` takes a UTF-8 folder path; `listNotes` returns sorted visible vault-relative UTF-8 Markdown paths with `/` separators; `readNote` returns opaque disk bytes. `Session::openVault`, `selectNote`, `setContent`, and `save` provide a headless editor flow: decoded text is strict UTF-8, an initial UTF-8 BOM is removed for editing and restored on save, and an invalid note or edit is refused. All failures report an error and retain the last selected note and unsaved text. Its save stages a same-directory replacement, compares the original bytes both before staging and immediately before replacement, and retries Windows sharing/lock failures with a fresh comparison before each attempt. It has the same best-effort external-write race, path-swap limitations, and replacement metadata/hard-link caveats described above; do not use it as a transaction or on valuable vaults without backups. `Session::getNotes` returns a borrowed read-only span of discovered paths, valid until the next vault opening or session destruction. Use `inkstow-tests` for headless coverage; the former Qt core and app have been retired. The portable `Session` now also detects clean reloads, dirty outside-change conflicts and missing notes; explicit reload reads the latest valid disk version, while Keep mine and merge require the reported outside bytes to remain current. Merges stay unsaved and put editable markers around overlapping changes. A missing selected note can be recreated in an existing folder only with exclusive creation, so a reappeared file is never replaced; a failed write may leave a partial new note while the session retains its edits. The existing best-effort path-swap limitation remains, especially for concurrent parent changes on Windows. Portable create, move, link resolution and native delete are implemented in #90; on Windows, native delete may be permanent with an explicit shell warning as described above. The portable recovery decisions and note actions are wired into the webview (#92, #93). The former Qt implementation was retired by maintainer decision without requiring feature-by-feature parity; do not infer unsupported WebView features from the old UI.

## Portable note actions (#90)

The Qt-free `Vault` can create empty notes (creating missing folders), move a note to an existing folder with optional conservative wikilink rewrites, resolve supported wikilinks, revalidate attachment paths, and move a note to the platform trash. Move takes expected source bytes; link updates preflight visible Markdown, reject unsupported relevant links, and preserve BOM bytes. A failure after the rename reports partial completion, not rollback. `trashNote` uses GIO on Linux, Finder's `NSFileManager` trash on macOS, and the interactive Windows Shell delete operation. Linux and macOS refuse if trash is unavailable; Windows asks to recycle but permits the user to confirm permanent deletion if recycling is impossible. Portable `Session` guards these actions against unsaved edits and refreshes its selection after a move or trash; the webview exposes these note actions with explicit move and trash choices.

For a platform trash smoke check, use a disposable vault outside the repo and invoke `Vault::trashNote` on a throwaway note. On Linux and macOS, confirm recovery in the desktop trash, then repeat without trash support and confirm refusal with the note unchanged. On a Windows desktop, run `build\\debug\\tests\\inkstow-tests.exe --test-case="Windows interactive trash smoke" --no-skip` to create and delete a uniquely named temporary note through the native shell; confirm it appears in the Recycle Bin. Then, in Recycle Bin Properties for the drive containing the printed temporary path, select "Don't move files to the Recycle Bin. Remove files immediately when deleted", rerun the command and **cancel the permanent-delete warning**. Confirm the command prints `file remains: 1`, and restore the original drive setting afterward. Never test against a personal vault. The headless tests inject an unavailable trash and check refusal without deleting the file.

## Offline system-webview editor (#91)

`inkstow-webview` is the only desktop executable. It uses the platform system webview and always bundles the offline frontend; Qt-only builds and `INKSTOW_BUILD_WEBVIEW=OFF` are no longer supported. Install Node.js 18+ and npm via `scripts/install --system` (the dotfiles installer already installs Node.js 22). Configure and build as above: the build runs `npm ci` from the pinned `src/frontend/package-lock.json` in `build/debug/webview-assets/`, bundles CodeMirror into a single HTML page, and embeds that page in the shell. A first build needs npm registry access; running the application does not. After changing frontend sources, rebuild; after changing package metadata, reconfigure and rebuild. Generated HTML, packages and C++ header are not checked in. For a clean offline build, pre-populate the CMake FetchContent downloads and npm cache.

Run `npm test --prefix build/debug/webview-assets` after building `inkstow-webview`; this controlled-bridge test also runs under `ctest --preset debug`. For a graphical smoke test, copy `tests/fixtures/sample` to a throwaway vault as shown above, run `./build/debug/inkstow-webview`, choose the copy with the empty-state Open vault button or File > Open vault…, select a note, edit, Undo (Ctrl+Z / Cmd+Z), and Save (Ctrl+S / Cmd+S). Check that switching notes or vaults while dirty shows an error and preserves text. For BOM verification use a disposable note created with `printf '\357\273\277Hello\n' > "$vault/BOM.md"`, save an edit, and inspect its bytes with `od -An -tx1 "$vault/BOM.md"` (first three bytes must remain `ef bb bf`). The webview preserves uniform CRLF, LF or lone-CR endings (and BOMs) when editing/saving; U+2028, U+2029 and NBSP remain literal characters. Notes with mixed CRLF/LF/CR endings are displayed read-only with a visible error, and Save refuses to write them to protect their bytes. The shell has a native folder picker (File > Open vault… / Ctrl+O or Cmd+O), saves the last successfully opened vault in local app settings, and reports a missing last vault on startup without replacing the saved path. Use a disposable copy for picker tests. The shell supports creating notes, explicit rename or move with optional link updates, and confirmed move to system trash; live preview renders Markdown on inactive lines. On Windows, cancel the permanent-delete warning if the Recycle Bin is unavailable. A shell-side best-effort watcher samples vault directories and the selected note's filesystem timestamps and size every 400 ms, and asks the bridge to refresh on changes. While visible, the frontend also refreshes every three seconds and on focus as a fallback when timestamps miss events. Dirty editor text is never replaced by a refresh. A clean note reloads; unsaved edits stay in the editor with a conflict bar offering **Reload from disk**, **Keep mine** or **Merge outside changes**. Merge stays unsaved, and overlapping edits have editable markers. A missing note offers **Save as new note** or **Discard edits**; Save as new refuses to overwrite a reappeared file. Failed decisions keep the editor text and show an error. Use only disposable vaults. File > Save and Edit > Undo remain available (Ctrl+S and Ctrl+Z; Cmd on macOS). Follow a link from the editor with Alt+Return (Option+Return on macOS); it is not a menu item. Following a supported attachment opens the validated file in the OS default app; dirty edits block navigation. Closing the window or choosing File > Quit (Cmd+Q on macOS) prompts Cancel, Save and quit, or Discard and quit for unsaved edits; Cancel receives initial focus. A refused save leaves the prompt and editor open.

For a native smoke check on Linux, macOS and Windows, copy `tests/fixtures/sample` to a throwaway folder, start `inkstow-webview`, open that folder with the native picker, edit and save with the menu and shortcut, then restart and confirm it reopens. Rename the throwaway folder while the app is closed and restart: the empty state should explain the missing vault and let you choose a new folder. Add a note from outside the app and check that it appears, then change the selected note outside the app while it is clean and while it is dirty; verify refresh and conflict respectively. Test focus return after an outside change too. Create a throwaway attachment and a wikilink to it, follow it with Alt+Return (Option+Return on macOS), and confirm the default app opens it. Edit a note, close the window and Cancel, try Save and quit with an outside conflict (the window must stay open), then explicitly Discard and quit. On macOS repeat with Cmd+Q. Do not test against a personal vault. CTest runs the real-webview `WebviewWindow*` case from `inkstow-tests` as `webview-conflict-window-tests` on all three supported platforms (under Xvfb on Linux), while the headless `inkstow-tests` cases run without a display. Its disposable vault includes a folder with two notes, and the case checks the rendered tree, collapse/expand, and nested-note selection in the real window. It also exercises native File menus, picker and attachment flows with injected OS services, native close, and macOS Cmd+Q cancel, conflict, and save paths. Manual platform smoke remains necessary for OS folder dialogs and default attachment handlers.

The CodeMirror editor renders headings, emphasis, inline and block code, lists, quotes, wikilinks and local or HTTP(S) Markdown links on inactive lines; the active line and every line in a selection show editable Markdown source. Click a rendered link to follow it, or press Alt+Enter (Option+Return on macOS) with the cursor inside link source. Ctrl+click (Cmd+click on macOS) follows source where pointer coordinates are available; an ordinary click on source edits it. There is no separate link-entry panel. Following a missing internal note link creates and opens an empty Markdown note in the source folder (or vault root for a root-relative link); explicit non-Markdown targets are not created. Wikilinks and attachments resolve through the portable core and refuse navigation with unsaved edits; external URLs go through a scheme-validated native opener. The Linux real-webview disposable-vault regression can save a screenshot with `INKSTOW_SCREENSHOT=/absolute/output.png xvfb-run -a ./build/debug/tests/inkstow-tests --test-case=WebviewWindow*`; an example is in `docs/screenshots/issue-95-live-preview.png`. This is not a cross-platform manual smoke result.

## Source and test layout

The native WebView host, bridge, watcher and platform adapters live in `src/desktop/`; its target definitions are in `src/desktop/CMakeLists.txt`. The offline CodeMirror UI, Live Preview, HTML, CSS and npm assets live in `src/frontend/`, bundled by the root CMake file. The shipped Qt-free `Vault` and `Session` with their filesystem and platform adapters live in `src/core/vault/` and build as `portable-core`; the public API remains in `inkstow::portable`. `vault-inspect` uses that same core. Keep vault operations and path safety in `Vault`, UI-independent state in `Session`, and presentation in the frontend. Headless vault/session, bridge, watcher, native navigation and real-window C++ cases live in `inkstow-tests`; JavaScript editor cases run under Node. Build the explicit `unit-tests` target before CTest.

AppImage static research is in `docs/obsidian-appimage-inspection.md`. Verified link and rename trials with disposable Obsidian vaults are in `docs/obsidian-runtime-observations.md`; use the project-local `/skill:obsidian-behavior` (at `.agents/skills/obsidian-behavior/SKILL.md`) to investigate further. To launch Inkstow on a headless display, drive it, and capture screenshots, use `.agents/skills/inkstow-ui/SKILL.md` and the real-window `inkstow-tests` case. Project skills are also exposed to Claude Code through the `.claude/skills` symlink.
