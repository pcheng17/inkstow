# Inkstow

Prototype of a non-Electron Markdown vault editor built in C++20 and Qt 6 Widgets. Its standalone vault core lists and reads existing Markdown notes and guards saves against external changes. A disposable example vault lives at `tests/fixtures/sample`.

## Install and run

On Debian/Ubuntu Linux (macOS notes follow):

```sh
sudo ./scripts/install --system   # Qt 6 development libraries, CMake, and C++ compiler
cmake --preset debug      # or: release
cmake --build --preset debug --parallel   # app and its core library only
cmake --build --preset debug --target unit-tests ui-tests --parallel
ctest --preset debug
./build/debug/inkstow     # run the desktop app on a graphical machine
```

On macOS, install Xcode or its Command Line Tools and [Homebrew](https://brew.sh), then run `./scripts/install --system` without `sudo` (it installs Homebrew's `cmake` and `qt`) and the same CMake build and CTest commands. Launch the macOS bundle with `open build/debug/Inkstow.app` instead of `./build/debug/inkstow`. CMake finds Homebrew's Qt through `brew --prefix qt`; pass `-DCMAKE_PREFIX_PATH=/path/to/qt` to use another Qt. If linking fails with `framework 'AGL' not found`, your Qt predates the macOS 26 SDK, which dropped AGL: run `brew upgrade qt` (6.9.0 fails; 6.11.2 works), then delete `build/` and reconfigure. The project and its presets require CMake 3.21+.

On other systems, install CMake 3.21+, a C++20 compiler (GCC 11+, Clang 14+, AppleClang 14+ / Xcode 14+, or MSVC 2022 / 19.30+), and Qt 6.4+ Core, Widgets and Test, then use the same CMake build and CTest commands. CI verifies Ubuntu 24.04 with `scripts/install`, macOS 15 with Xcode and Qt 6.8.3, and Windows 2022 with MSVC 2022 and Qt 6.8.3; these runner configurations are the supported platform build checks. The application uses a light Qt palette even when the desktop's default is dark.

Open a vault folder with **Open vault…** (also **File > Open vault…**, Ctrl+O / Cmd+O), which shows a folder picker. Inkstow reopens the last vault on the next launch; if that folder is gone or can't be opened, it shows the empty state with the reason. To avoid altering the checked-in fixture, first copy it to a throwaway directory:

```sh
vault=$(mktemp -d)
cp -a tests/fixtures/sample/. "$vault/"
printf '%s\n' "$vault"
```

Open that folder in Inkstow. Only `Welcome.md` and `Folder/Second note.md` should appear; dot-prefixed files and folders are excluded from discovery. Edit a note: the header shows its name without `.md` and a ● while there are unsaved edits. Save with Ctrl+S (Cmd+S on macOS), confirm the ● clears and the copied file changes on disk. Check that an unsaved note cannot be switched away from, and that **Open vault…** refuses to switch vaults until you save. Type `Folder/New note` under the note list and press **Create**: the copy should gain `Folder/New note.md`, selected and empty. Select a clean note and choose **Note > Rename / move…** (F2, or right-click the note in the tree), enter a new vault-relative path in an existing folder, and confirm **Update links** (the default). Cancel changes nothing; **Don't update** explicitly warns links may break. Choose **Note > Delete…** (or right-click the note), then **Move to trash**: the note should move to the system trash and leave the list. With no unsaved edits, change the open note from another program: Inkstow should reload it and say so in the status bar. To test a conflict, edit a note in Inkstow without saving, modify the same file externally, then save (Ctrl+S / Cmd+S): it should report a conflict, retain the unsaved editor text without overwriting the external version, and show a bar with **Reload from disk** (discard your edits), **Keep mine** (replace the external version), and **Merge outside changes** (merge into the editor without saving). Overlapping edits get editable conflict markers; review and Save explicitly. To try wikilinks, open a disposable copy of `tests/fixtures/links`, place the cursor inside `[[Twin]]` in `A/Source.md`, and choose **Note > Follow link** (Alt+Return; Option+Return on macOS), or Ctrl+click (Cmd+click on macOS) the link. The expected targets and unresolved Obsidian-compatibility questions are in that fixture's `README.txt`. Unsaved edits block following a link to another note or opening an attachment. To check Markdown highlighting, open a disposable copy of `tests/fixtures/highlighting`: frontmatter is muted, headings are larger, emphasis is bold or italic, wikilinks are coloured, and code is monospace, while the lines that file describes as malformed stay plain. Highlighting only styles the text; markup stays visible and saved bytes are unchanged.

## Sandcastle/Pi issue workflow (Linux Docker)

This optional unattended workflow needs Docker, Node.js 22.19+, npm, `gh` logged into `pcheng17/inkstow` with issue/PR access, and an `origin` remote with push access. Use a clean checkout; `npm ci` installs the pinned local harness dependencies. Build the pinned sandbox image once, then sign in to Pi's **dedicated** profile inside an interactive container (type `/login` and follow its instructions):

```sh
npm ci
npm run sandcastle:build-image
npm run sandcastle -- --login
npm run sandcastle -- --check 123  # read-only GitHub eligibility/branch gate and isolated Pi auth check
npm run sandcastle -- 123          # implement issue #123
```

The host checks `ready-for-agent`, native blockers, parent and comments, refuses an existing local or remote `sandcastle/issue-123` branch, and fetches `origin/main`. It creates a new worktree on that base, preflights the sandbox's `openai/gpt-6-sol` login (the provider name used by Pi's OpenAI OAuth flow in this image), and only then allows any issue updates. The implementer follows TDD, simplifies in the same session, and commits green slices. The host requires clean committed changes, configures WebView ON, builds the app, WebView, both test targets and `vault-inspect`, runs CTest and, for C++ changes, checks clang-format and `scripts/check-clang-tidy.py`. Fresh serial Standards and Spec reviewers and a fresh PR writer get only Pi's read tool and a host-captured diff; HEAD and status are checked after each pass. Up to two review fix rounds are allowed. Only the host pushes and opens a PR; it never merges. The host then comments with the PR URL or marks a blocked run `needs-info`.

The image checks out a pinned commit of `pcheng17/harness-kit` and runs `uv run --locked harness-kit install --harness pi`, installing its Pi package, agents, skills, and instructions. The issue workflow still asks each pass to work alone; installation does not enable agent delegation in those prompts. Harness Kit does not include `pi-web-access`, so its web-research agents require that separate extension if used.

The login profile lives at `~/.local/share/inkstow/sandcastle-pi/agent` (private permissions), not the regular host `~/.pi/agent`; do not copy host credentials into it. The container receives this profile and the worktree, not host `gh` credentials. It mounts the profile at a separate path and links only its auth and model-store files into Pi's config directory; mounting over `~/.pi/agent` would hide the package registration installed in the image. Existing profile `settings.json` is not loaded inside the container. `--check` does not create a branch, comment, change labels, push, or open a PR; it does fetch `origin/main` locally. Auth/image/network or verification failures stop the run. A failed run can leave a durable branch (and a dirty worktree is preserved); inspect that branch before rerunning or removing it. Logs are under `.sandcastle/logs/`, and verification prints bounded output. The local gate requires Linux Docker/WebKitGTK; macOS and Windows build/test checks remain CI's responsibility. Never point manual verification at a personal vault; use `tests/fixtures/sample` or a throwaway vault.

## Making a release

Releases are started manually from **Actions > Release > Run workflow**, on `main`. First merge a PR changing `project(Inkstow VERSION ...)` in `CMakeLists.txt` to the intended `MAJOR.MINOR.PATCH` version (for the first `v0.1.0` release, the existing value is sufficient). Enter that version without the `v` in the workflow form. The workflow refuses non-`main` runs, version mismatches, and existing tags. It builds and runs CTest on all three release runners before creating the immutable `vMAJOR.MINOR.PATCH` tag and GitHub Release. Do not create the tag by hand. A failed build creates no release; if publishing fails after the tag or draft release was created, inspect that draft and the workflow logs before any manual recovery. Do not retag an existing release to a different commit.

The release contains unsigned portable bundles with Qt included: a Linux x86_64 tarball (extract and run `inkstow/AppRun` on an X11 desktop; built on Ubuntu 24.04 and requires a compatible glibc/system graphics stack), a macOS arm64 zip file for Apple silicon (unzip and open `Inkstow.app`; no Intel Mac download is provided), and a Windows x86_64 zip file (unzip and run `inkstow.exe`). It also contains `SHA256SUMS`. These are not installers. macOS Gatekeeper and Windows SmartScreen may warn about unnotarized/unsigned applications; do not bypass security warnings for downloads you cannot verify. PR CI builds and tests the app on these systems; the release workflow runs its Linux, macOS and Windows release build, CTest, bundle and smoke checks on PRs without publishing. Only manual dispatch on `main` publishes a release. A first real release should be downloaded and smoke-tested on each target OS before announcing it.

## Pre-commit hook

The `.githooks/pre-commit` hook auto-formats staged `.h` and `.cpp` files with `clang-format` before each commit. Install `clang-format` 21 or newer (older versions reformat already-formatted code) and activate the hook once after cloning:

```sh
git config core.hooksPath .githooks
```

## Clang-tidy check

Configure with WebView enabled and build all checked targets so the compilation database includes the shell and test sources, then run the same check as CI from the repository root:

```sh
cmake --preset debug -DINKSTOW_BUILD_WEBVIEW=ON
cmake --build --preset debug --target inkstow inkstow-webview unit-tests ui-tests vault-inspect --parallel 2
python3 scripts/check-clang-tidy.py
```

The script uses `clang-tidy` on your PATH by default; pass `--clang-tidy clang-tidy-18` to use CI's pinned executable. It refuses missing compilation entries and treats lint warnings as errors. On Linux it requires the Linux navigation implementation and native-navigation test compilation entries (the latter needs Xvfb at configure time); on macOS and Windows it skips these Linux-only sources. Platform-specific macOS/Windows navigation implementations are not covered by this check. The clang-tidy CI job runs on Linux.

## Headless tests

The default build compiles `inkstow` and its `core` dependency. Build `unit-tests` (the `core-tests`, `highlighter-tests`, and `portable-core-tests` executables) and `ui-tests` explicitly before running CTest; CTest runs all four registered tests without a graphical display. The core and portable core tests use filesystem fixtures, the highlighter tests use a headless `QGuiApplication`, and the UI tests use an offscreen `QApplication` to exercise the window. These names describe build/runtime grouping, not a strict unit-versus-end-to-end split. To inspect the fixture vault, build `vault-inspect` explicitly with `cmake --build --preset debug --target vault-inspect`, then run `./build/debug/vault-inspect tests/fixtures/sample` or pass another throwaway vault path.

## Boundaries and limitations

This is an early prototype, **not** a safe replacement for Obsidian on valuable vaults. It can rename/move individual notes but cannot rename folders or render Live Preview. Link updates preflight all discoverable Markdown notes, refuse complex relevant wikilinks (aliases, fragments, embeds), invalid UTF-8, and unresolved relevant links; they rewrite simple affected links to root-qualified paths without `.md`, rather than copying Obsidian's shortest-link serialization. If an extensionless file would shadow a rewritten link, or a basename already ends in `.md`, link updates refuse the move before changing any files. Names containing wikilink delimiters (`#`, `|`, `[`, `]`, or newlines) are also refused for link updates. Case-only renames are not supported on case-insensitive filesystems. UTF-8 BOMs are preserved. Choosing not to update links may break them. The move and rewrites are not a filesystem transaction: later write failures may leave a moved note and partially updated links (the error reports this). External writes can race preflight and per-file replacement. **Follow link** resolves Markdown notes and opens attachments in the system's default app, but its target ordering and case handling are provisional and have not been checked against a running Obsidian. Heading fragments select the file, not a position within it; block references and embeds are not supported. It watches the open note: outside changes reload a clean editor, while unsaved edits are kept and a bar offers to reload from disk or keep your version. **Keep mine** only replaces the outside version that was reported, and reloading can be undone. **Merge outside changes** combines disjoint line edits and marks overlapping edits, including deletion versus change. Very large notes are refused by the line merge rather than exhausting memory. The merged editor text remains unsaved and Save still refuses a newer outside change. If a note is deleted outside Inkstow while you have unsaved edits, the bar offers **Save as new note** to recreate the selected path without replacing a reappeared file, or **Discard edits**. The note list refreshes when watched vault folders change or when the window is reactivated. Large vaults may exceed the OS limit on watched paths, so some changes may not appear until reactivation. New notes need a vault-relative path whose folders and name don't start with `.`; `.md` is added when missing, and an existing file is never replaced. The current Qt app's Delete action only moves notes to system trash; where there is no trash, it refuses rather than deleting permanently. The separate portable core uses the interactive Windows Shell instead: if Windows cannot recycle a note, it can offer permanent deletion. **Cancel that prompt if you need the note to remain recoverable**. Confirming permanent deletion cannot be undone from the Recycle Bin; see "Portable note actions" below. Saves replace the file using `QSaveFile`. Replacement can change inode and metadata; hard links are not preserved. The Qt editor preserves uniform CRLF, LF and lone-CR line endings when editing; a note with mixed line endings keeps its exact bytes when opened and saved unchanged, but after an edit all its line endings become LF. Use a backup before editing mixed-ending notes. Markdown must be valid UTF-8 to open in the editor. The vault core rejects path traversal and never reads or writes a note through a symlink, but filesystem races have not been hardened. Use only disposable copies for now.

### Save conflict guarantee

Inkstow compares a note's disk bytes with the last loaded or saved bytes before saving, then compares again just before committing the staged replacement. If either comparison finds different bytes, the save is refused and your unsaved edits stay in the editor. This is best-effort conflict detection, **not** a guarantee that outside changes cannot be lost: another program (including another Inkstow instance) can write after the final comparison and before the replacement, and its write may be overwritten. Atomic replacement keeps Inkstow from leaving a partially written note, but does not make the comparison and replacement atomic together. On Windows, a transient lock can prevent atomic replacement; Inkstow retries a few times, checking the original bytes before each attempt, and leaves edits unsaved if the lock persists. Inkstow does not coordinate saves with other processes or guarantee recovery of a write lost in that window. Use independent backups for valuable vaults.

## Portable vault and recovery migration (#88, #89)

`portable-core` (`src/core/portable/`) is a standalone C++20 library with no Qt dependency. `inkstow::portable::Vault::open` takes a UTF-8 folder path; `listNotes` returns sorted visible vault-relative UTF-8 Markdown paths with `/` separators; `readNote` returns opaque disk bytes. `Session::openVault`, `selectNote`, `setContent`, and `save` provide a headless editor flow: decoded text is strict UTF-8, an initial UTF-8 BOM is removed for editing and restored on save, and an invalid note or edit is refused. All failures report an error and retain the last selected note and unsaved text. Its save stages a same-directory replacement, compares the original bytes both before staging and immediately before replacement, and retries Windows sharing/lock failures with a fresh comparison before each attempt. It has the same best-effort external-write race, path-swap limitations, and replacement metadata/hard-link caveats described above; do not use it as a transaction or on valuable vaults without backups. `Session::getNotes` returns a borrowed read-only span of discovered paths, valid until the next vault opening or session destruction. Use `portable-core-tests` for headless coverage; the current Qt core and app stay unchanged during migration. The portable `Session` now also detects clean reloads, dirty outside-change conflicts and missing notes; explicit reload reads the latest valid disk version, while Keep mine and merge require the reported outside bytes to remain current. Merges stay unsaved and put editable markers around overlapping changes. A missing selected note can be recreated in an existing folder only with exclusive creation, so a reappeared file is never replaced; a failed write may leave a partial new note while the session retains its edits. The existing best-effort path-swap limitation remains, especially for concurrent parent changes on Windows. Portable create, move, link resolution and native delete are implemented in #90; on Windows, native delete may be permanent with an explicit shell warning as described above. The portable recovery decisions and note actions are wired into the webview (#92, #93). Retire the corresponding Qt implementation only after migration parity is demonstrated.

## Portable note actions (#90)

The Qt-free `Vault` can create empty notes (creating missing folders), move a note to an existing folder with optional conservative wikilink rewrites, resolve supported wikilinks, revalidate attachment paths, and move a note to the platform trash. Move takes expected source bytes; link updates preflight visible Markdown, reject unsupported relevant links, and preserve BOM bytes. A failure after the rename reports partial completion, not rollback. `trashNote` uses GIO on Linux, Finder's `NSFileManager` trash on macOS, and the interactive Windows Shell delete operation. Linux and macOS refuse if trash is unavailable; Windows asks to recycle but permits the user to confirm permanent deletion if recycling is impossible. Portable `Session` guards these actions against unsaved edits and refreshes its selection after a move or trash; the webview exposes these note actions with explicit move and trash choices.

For a platform trash smoke check, use a disposable vault outside the repo and invoke `Vault::trashNote` on a throwaway note. On Linux and macOS, confirm recovery in the desktop trash, then repeat without trash support and confirm refusal with the note unchanged. On a Windows desktop, run `build\\debug\\tests\\portable-core-tests.exe --trash-smoke` to create and delete a uniquely named temporary note through the native shell; confirm it appears in the Recycle Bin. Then, in Recycle Bin Properties for the drive containing the printed temporary path, select "Don't move files to the Recycle Bin. Remove files immediately when deleted", rerun the command and **cancel the permanent-delete warning**. Confirm the command prints `file remains: 1`, and restore the original drive setting afterward. Never test against a personal vault. The headless tests inject an unavailable trash and check refusal without deleting the file.

## Offline system-webview editor (#91)

`inkstow-webview` is a separate executable; the Qt `inkstow` app remains available. The shell is enabled by default; configure with `cmake --preset debug -DINKSTOW_BUILD_WEBVIEW=OFF` for Qt-only builds without WebKitGTK, Node/npm or fetched webview/json dependencies, and use `-DINKSTOW_BUILD_WEBVIEW=ON` to re-enable it. Install Node.js 18+ and npm via `scripts/install --system` (the dotfiles installer already installs Node.js 22). Configure and build as above: the build runs `npm ci` from the pinned `src/webview/package-lock.json` in `build/debug/webview-assets/`, bundles CodeMirror into a single HTML page, and embeds that page in the shell. A first build needs npm registry access; running the application does not. After changing frontend sources, rebuild; after changing package metadata, reconfigure and rebuild. Generated HTML, packages and C++ header are not checked in. For a clean offline build, pre-populate the CMake FetchContent downloads and npm cache.

Run `npm test --prefix build/debug/webview-assets` after building `inkstow-webview`; this controlled-bridge test also runs under `ctest --preset debug`. For a graphical smoke test, copy `tests/fixtures/sample` to a throwaway vault as shown above, run `./build/debug/inkstow-webview`, enter the copy's absolute folder path, select a note, edit, Undo (Ctrl+Z / Cmd+Z), and Save (Ctrl+S / Cmd+S). Check that switching notes or vaults while dirty shows an error and preserves text. For BOM verification use a disposable note created with `printf '\357\273\277Hello\n' > "$vault/BOM.md"`, save an edit, and inspect its bytes with `od -An -tx1 "$vault/BOM.md"` (first three bytes must remain `ef bb bf`). The webview preserves uniform CRLF, LF or lone-CR endings (and BOMs) when editing/saving; U+2028, U+2029 and NBSP remain literal characters. Notes with mixed CRLF/LF/CR endings are displayed read-only with a visible error, and Save is disabled to protect their bytes. Mixed-ending editing remains unresolved in #63, including the separate Qt editor. The shell has a native folder picker (File > Open vault… / Ctrl+O or Cmd+O), saves the last successfully opened vault in local app settings, and reports a missing last vault on startup without replacing the saved path. Use a disposable copy for picker tests. The shell supports creating notes, explicit rename or move with optional link updates, and confirmed move to system trash; live preview renders Markdown on inactive lines. On Windows, cancel the permanent-delete warning if the Recycle Bin is unavailable. A shell-side best-effort watcher samples vault directories and the selected note's filesystem timestamps and size every 400 ms, and asks the bridge to refresh on changes. While visible, the frontend also refreshes every three seconds and on focus as a fallback when timestamps miss events. Dirty editor text is never replaced by a refresh. A clean note reloads; unsaved edits stay in the editor with a conflict bar offering **Reload from disk**, **Keep mine** or **Merge outside changes**. Merge stays unsaved, and overlapping edits have editable markers. A missing note offers **Save as new note** or **Discard edits**; Save as new refuses to overwrite a reappeared file. Failed decisions keep the editor text and show an error. Use only disposable vaults. File > Save and Note > Undo / Follow link share their operations with the editor controls (Ctrl+S, Ctrl+Z and Alt+Return; Cmd / Option on macOS). Following a supported attachment opens the validated file in the OS default app; dirty edits block navigation. Closing the window or choosing File > Quit (Cmd+Q on macOS) prompts Cancel, Save and quit, or Discard and quit for unsaved edits; Cancel receives initial focus. A refused save leaves the prompt and editor open.

For a native smoke check on Linux, macOS and Windows, copy `tests/fixtures/sample` to a throwaway folder, start `inkstow-webview`, open that folder with the native picker, edit and save with the menu and shortcut, then restart and confirm it reopens. Rename the throwaway folder while the app is closed and restart: the empty state should explain the missing vault and let you choose a new folder. Add a note from outside the app and check that it appears, then change the selected note outside the app while it is clean and while it is dirty; verify refresh and conflict respectively. Test focus return after an outside change too. Create a throwaway attachment and a wikilink to it, follow it with Alt+Return (Option+Return on macOS), and confirm the default app opens it. Edit a note, close the window and Cancel, try Save and quit with an outside conflict (the window must stay open), then explicitly Discard and quit. On macOS repeat with Cmd+Q. Do not test against a personal vault. CTest runs the real-webview `webview-conflict-window-tests` on all three supported platforms (under Xvfb on Linux). It exercises native File menus, picker and attachment flows with injected OS services, native close, and macOS Cmd+Q cancel, conflict, and save paths. Manual platform smoke remains necessary for OS folder dialogs and default attachment handlers.

The CodeMirror editor renders headings, emphasis, inline and block code, lists, quotes, wikilinks and local or HTTP(S) Markdown links on inactive lines; the active line and every line in a selection show editable Markdown source. Click a rendered link to follow it, or press Alt+Enter (Option+Return on macOS) with the cursor inside link source. Ctrl+click (Cmd+click on macOS) follows source where pointer coordinates are available; an ordinary click on source edits it. Wikilinks and attachments resolve through the portable core and refuse navigation with unsaved edits; external URLs go through a scheme-validated native opener. The Linux real-webview disposable-vault regression can save a screenshot with `INKSTOW_SCREENSHOT=/absolute/output.png xvfb-run -a ./build/debug/tests/webview-conflict-window-tests`; an example is in `docs/screenshots/issue-95-live-preview.png`. This is not a cross-platform manual smoke result.

## Source and test layout

The native WebView host, bridge, watcher and platform adapters live in `src/desktop/`; its target definitions are in `src/desktop/CMakeLists.txt`. Bundled HTML, JavaScript, CSS and npm assets remain in `src/webview/` and are built by the root CMake file. The Qt app and tests remain in place during this migration.

Keep vault filesystem operations and UI-independent session state in `src/core/` (`Vault` and `Session`), which depends on Qt Core but not Qt Widgets. Keep editor presentation, highlighting, window widgets, settings adapter, and theme in `src/ui/`; this module can depend on `core`. Entry points remain at `src/main.cpp` and `src/VaultInspect.cpp`. Place new files by responsibility, not by which test executable covers them: the highlighter belongs to `ui/` even though its tests run without a window. Add core/session coverage to `core-tests`, standalone document-format coverage to `highlighter-tests`, and window interaction coverage to `ui-tests`; preserve their respective `QCoreApplication`, `QGuiApplication`, and `QApplication` runtimes. Build test executables with their explicit targets before CTest.

AppImage static research is in `docs/obsidian-appimage-inspection.md`. Verified link and rename trials with disposable Obsidian vaults are in `docs/obsidian-runtime-observations.md`; use the project-local `/skill:obsidian-behavior` (at `.agents/skills/obsidian-behavior/SKILL.md`) to investigate further. To launch Inkstow on a headless display, drive it, and capture screenshots, use `scripts/inkstow-headless.sh` as described in `.agents/skills/inkstow-ui/SKILL.md`. Project skills are also exposed to Claude Code through the `.claude/skills` symlink.
